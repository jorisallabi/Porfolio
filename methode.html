Comment je travaille sur un laboratoire

Je commence par définir ce que je veux faire fonctionner et comment je vais vérifier le résultat. Ensuite, je construis progressivement, je garde une copie des configurations et je teste aussi les scénarios de panne.

Quand quelque chose ne marche pas, je note le symptôme avant de chercher une cause. Je vérifie les journaux, les routes, les états des interfaces et les dépendances. Je change une chose à la fois pour comprendre ce qui a réellement corrigé le problème.

Un exemple : le cluster Hyper-V

Dans mon laboratoire à deux hôtes, la migration à chaud d'une VM a provoqué une interruption du ping inférieure à 15 secondes. Lors de l'extinction brutale d'un hôte, la VM a redémarré sur le second après environ cinq minutes.

Je n'ai pas confirmé la cause exacte de ce délai. La virtualisation imbriquée peut contribuer à la lenteur, mais je n'ai pas fait de comparaison sur matériel physique. Je garde donc cette limite dans la fiche plutôt que de présenter une explication comme certaine.

Ce que je consigne

  • La configuration et les versions réellement utilisées.
  • Les commandes et vérifications qui permettent de reproduire le test.
  • Le résultat observé, y compris les interruptions et les échecs.
  • Les limites connues et les points que je n'ai pas encore testés.

Je ne présente pas un objectif d'apprentissage comme une réalisation. Si un test manque, je l'indique.
